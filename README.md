# Návrat — Phase 0 prototype

Sales-demo prototype of a managed reactivation service for Czech car repair
shops: find customers who stopped coming, send them an approved SMS campaign,
and prove how much revenue came back.

> **All data is fictional.** Three demo shops, their customers, vehicles,
> campaigns and results are generated by a deterministic seed. Every page
> carries an "Ukázková data" bar; money figures shown to shop owners carry a
> "Demo" tag. No SMS is ever sent (mock provider only).

The full product specification is in [docs/spec.pdf](docs/spec.pdf) (text
export: [docs/spec.md](docs/spec.md)). This repository implements **Phase 0
only** (spec §29). Phase 0 decisions: [ADR-001](docs/decisions/ADR-001-phase-0-demo-architecture.md).

## Run it

Requirements: Node.js 22+ and pnpm. No Docker, database or API keys.

```bash
pnpm install
pnpm dev
```

Open http://localhost:3000. For a meeting, a production build is snappier:

```bash
pnpm build
pnpm start
```

Checks: `pnpm check` (typecheck, lint, format, unit tests with `lib/domain` coverage ≥ 90 %).
End-to-end: `pnpm test:e2e` (Playwright on the installed Microsoft Edge; runs the full demo
flow and a 390 px phone pass on its own dev server, port 3100).

### Running against local Supabase

Needs Docker Desktop.

```bash
pnpm db:start
```

```bash
pnpm env:local
```

```bash
pnpm db:seed
```

```bash
pnpm dev:supabase
```

Open http://localhost:3001/login. `pnpm db:seed` loads the three shops of spec §31 (Autoservis Dvořák,
Pneu & Servis Horák, Garáž U Nádraží: 5 600 customers, 6 620 vehicles, ~24 000 visits) and resets the
seeded accounts: `operator@navrat.example.cz` (platform admin) and `majitel@…` / `vedouci@…` on
`dvorak`, `horak` and `nadrazi.example.cz`. Their password is `SEED_USER_PASSWORD` in
`.env.supabase.local` (generated locally, never committed). Re-running the seed restores everything,
including removing the operator's MFA factor. Your own operator account: `pnpm admin:create <email> <password>`.
The operator enrols TOTP MFA on first sign-in. Invitation and
password-reset emails land in the local Mailpit inbox at http://127.0.0.1:54324. Screens that still use
demo data show "Tato část se připravuje" until their slice moves them to real data.

Tests on the local stack: `pnpm db:test` (pgTAP) and `pnpm test:e2e:supabase` (auth flows and the
seeded world; run `pnpm db:seed` first). Messy import fixtures (Windows-1250 CSV, two-sheet XLSX,
duplicates, broken files) live in `supabase/seed/fixtures` with a manifest; `pnpm db:fixtures` regenerates them. `pnpm jobs:nightly` runs the nightly lifecycle recompute by hand.
Without Docker, `pnpm db:test:local` applies every migration to an in-process
PGlite (real PostgreSQL in WebAssembly) with a minimal Supabase stub and runs the same pgTAP files through
a small pgTAP shim; it is part of `pnpm check` and CI.
Configuration: `supabase/config.toml` (sign-up disabled, TOTP MFA, 12-char passwords).
All variables: [.env.example](.env.example).

## The 5-minute demo

A **Průvodce ukázkou** card (bottom right, collapsible) follows the scenario
and always shows the next click. Press **Resetovat demo** in it before each
meeting to restore the starting numbers.

| #   | Screen                    | What to show                                                                                                                                                                                         |
| --- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Přehled** (admin)       | 3 clients, MRR, messages, recovered revenue; _Vyžaduje pozornost_ lists real operator issues (approval waiting, low conversion, no campaign running) and an unused opportunity at Autoservis Dvořák. |
| 2   | **Autoservis Dvořák**     | Opportunity cards with expected revenue; the recommended one is "Bez návštěvy 12+ měsíců" (~190 customers, ~44 000 Kč). Month KPIs: 52 300 Kč, 11 returns, 14 bookings, 218 SMS, ROI 10,5×.          |
| 3   | **Nová kampaň → Segment** | Eligible vs excluded customers with reasons (opted out, no legal basis, no mobile, contacted recently), 10 % holdout, expected revenue (6 % × median job).                                           |
| 4   | **Zpráva**                | "Vygenerovat zprávu pomocí AI" → 3 Czech variants, rewrite chips. Toggle **Odstranit diakritiku**: 3 → 2 SMS per message and the cost drops.                                                         |
| 5   | **Náhled / Kontrola**     | Preview for real recipients (one without a vehicle shows the fallback wording); totals: SMS segments, cost, expected revenue, opt-out present.                                                       |
| 6   | **Simulace odeslání**     | Live progress through the mock SMS provider with a few failures and delivery reports. Nothing is really sent.                                                                                        |
| 7   | **Výsledky kampaně**      | A customer "calls": click **Objednal se**, then **Dokončeno** and type e.g. 6 800. The toast offers the client view.                                                                                 |
| 8   | **Klientský pohled**      | What the owner sees, read-only with an amber banner: _Vrácené tržby tento měsíc_ now 59 100 Kč, ROI updated, the customer at the top of _Nedávno vrácení zákazníci_, 12-month chart vs subscription. |

Other screens worth a click: customer detail (vehicles + visit timeline +
campaign history), **Segmenty** (all 9 presets with counts), the client
**Výsledky** page (by month / campaign / segment, holdout comparison).

## Demo data

| Shop                            | Profile                                                                                                                                                                                      |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Autoservis Dvořák s.r.o., Kolín | Main demo shop: 1 800 customers, 2 300 vehicles, 5 years of visits, 10 months of campaigns, Growth 4 990 Kč. This month: 218 messages, 14 bookings, 11 completed jobs, 52 300 Kč, ROI 10,5×. |
| Pneu & Servis Horák, Brno       | 3 200 customers, tyre-heavy, many fixed lines; one low-conversion campaign and one waiting for client approval (alerts).                                                                     |
| Garáž U Nádraží, Jihlava        | 600 customers, sparse data (no job values, 30 % without vehicle), no campaign yet (alert).                                                                                                   |

Dates are relative to the day the server starts, so the current month always
holds the presentation numbers. Names are common Czech names with correct
female surname forms; phones are random but valid-format, emails use
`example.cz` / `example.com`.

## What is mocked in Phase 0

| Area           | Phase 0                                                                            | Phase 1 replacement                                                                                  |
| -------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Database       | In-memory store, deterministic seed                                                | Supabase Postgres (EU), SQL migrations, RLS on every table, composite FKs                            |
| Auth           | None; cookie-based read-only client view                                           | Supabase Auth, invite-only, admin TOTP MFA, permissions map, audited support view                    |
| AI             | Library templates behind `lib/ai/client.ts`, real validator                        | Vercel AI SDK with a real provider, versioned prompts, `ai_generations` log                          |
| SMS            | Mock provider (`lib/providers/sms/mock.ts`), dispatcher ticks driven from the page | Czech gateway adapter, Inngest dispatcher with idempotency and rate limits, DLR webhooks, follow-ups |
| Alerts / stats | Computed on page load                                                              | Scheduled health check writing `alerts`, `company_monthly_stats`                                     |
| Segments       | Rule JSON evaluated in TypeScript                                                  | Same JSON compiled to SQL (`compileSegment`)                                                         |
| Not built      | Imports, opt-out page, approvals, audit log, billing, email                        | Phase 1 slices per spec §40                                                                          |

## Project structure

```
app/(admin)/admin/…      operator app: overview, clients, company tabs, builder, campaign detail
app/(client)/app/…       client app (read-only support view in Phase 0)
components/              ui/ primitives, shell/, demo/ (demo bar, guide), feature folders
lib/domain/              pure business logic: lifecycle, segments, contact rules, messaging, KPIs, alerts
lib/db/                  types (= SQL schema), demo store + seed, queries, mutations
lib/providers/sms/       provider interface + mock adapter
lib/ai/                  AI wrapper (mock), versioned prompt, template validator
lib/actions/             thin server actions: Zod → domain → result
messages/cs.json         all UI strings (next-intl)
tests/unit/              Vitest: domain, messaging, seed numbers
docs/                    spec, ADRs
```
